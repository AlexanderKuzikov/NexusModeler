# NexusModeler — контракт

Единственный источник истины по слотам и по выгрузке пропсов. Меняется только решением владельца.

## Зачем реестр

Слот — это **обещание вида, а не картинка**. Сорок номеров общие для всех сетов: при смене сета на той
же позиции встанет модель с тем же номером, и карта останется читаемой. Если номер ничего не значит,
то место с густой елью станет одиноким кактусом, и смена сета ломает карту.

**Номера не переставляются и не добавляются.** Это контракт с игрой.

## Правило полноты

**Каждый сет обязан заполнить все сорок слотов.** Пропущенный номер в наборе означает дыру на карте и
ломает обещание номера. Проверка обязана падать на пропуске, а не печатать его.

## Требования к модели

**Читаемость, а не детализация.** В игре камера даёт 11–17 пикселей на единицу. Дерево высотой 7 это
80–120 пикселей, череп высотой 0.5 — **6–9 пикселей**. Значит:

- мелкое читается **силуэтом и светлотой**; череп это тёмная глыба с двумя провалами глаз, а не анатомия;
- модели одного вида различаются **пропорцией и наклоном**, а не оттенком;
- **силуэт важнее материала**: сначала форма, потом поверхность.

**Технические ограничения.**

- **Без скелетов и без клипов.** Ветер в игре делает вершинный шейдер.
- Только `Mesh` и `Group`. Ни материалов, ни текстур, ни изображений: цвет живёт в `COLOR_0`.
- **Файлы обязаны грузиться обычным `GLTFLoader`**: без расширений, своих нод и нестандартных атрибутов.
- `emissiveNode` не требуется: в игре это поле необязательное.
- **Цвета свои.** Пропс лежит на своей клетке, а не в общей сцене заказчика.
- Основание садится в ноль: модель не висит и не уходит вниз.

**Размеры в единицах игры, где одна клетка карты равна одной единице.**

| `kind` | Высота | Радиус |
|---|---|---|
| `tree` | 3.0…7.0 | 0.7…1.6 |
| `bush` | 0.5…1.6 | 0.6…1.4 |
| `rock` | 0.4…2.4 | 0.4…1.6 |
| `debris` | 0.25…1.2 | 0.5…1.8 |
| `ruin` | 1.2…4.0 | 0.6…1.8 |
| `bone` | 0.25…0.8 | 0.4…1.3 |

**Радиус измеряется на посаженной модели:** посадка сдвигает центр в ноль, и замер до посадки даёт
число меньше настоящего. Порядок: масштаб → посадка → замер.

## Форма выгрузки

Одна модель — один файл. Имя записи `land.<сет>.<NN>`, имя файла `land-<сет>-NN.glb`, где `NN` —
двузначный номер слота.

Манифест — тот же формат, что у башен и существ, плюс блок `land`:

```json
{
  "id": "land.forest.07",
  "file": "land-forest-07.glb",
  "bytes": 41233,
  "contentHash": "sha256:…",
  "triangles": 574,
  "land": { "slot": 7, "kind": "tree", "footprint": 1, "solid": true }
}
```

`land` обязателен для любой записи, чей `id` начинается с `land.`, и запрещён у любой другой. Это граница
между производителями: башни и существа — `NexusDefense`, рельеф — здесь.

`bytes` и `contentHash` обязаны совпадать с диском по каждой записи.

## Куда это движется

Структура слотов сейчас живёт здесь, в тексте контракта. Позже она переезжает в файл кожи
(`Burrow3D`) полем `tiles`, и проверка полноты набора переезжает туда же. **Списков в контракте быть
не должно:** игра не должна знать ни имён моделей, ни наборов, иначе первый же новый слот потребует
правки в игре.
